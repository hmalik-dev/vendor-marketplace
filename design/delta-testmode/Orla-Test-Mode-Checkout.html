The strip is additive and nothing else moves
Same fields, same summary, same button, same total. If test mode changed any other pixel, the thing being tested would stop being the thing that ships. It pushes the page down 34px rather than overlaying, so nothing is covered.
Checkout only — and why not global
A strip on every screen becomes furniture within an hour and stops being read. Payment is the only surface where the consequence of confusion is someone thinking they were charged, so it appears there and nowhere else — including the declined state on 21 and the refund block on 33, which inherit it because they are the same page.
Not steel, not gold
Steel would file it with we're loading something, gold with waiting on you, and both are claims about the booking. Ink with a single amber dot belongs to no state family, and mono type says developer surface before the sentence is even read.
Gated on the key, not a flag
Render when the publishable key starts pk_test_ — not on a build flag or an env name, which can disagree with the key actually in use. A production key means no strip, with no way to force one on.
39bDeclined & refund block — the strip inheritedThe other two surfaces of the same page, drawn so the hand-off doesn't have to take “it inherits it” on trust. Frames 21 and 33 are the declined state and the refund block, both at /bookings/[requestId]/checkout — so the strip is the same element in the same place, not a second implementation. Worth seeing because 21 is the one place ink meets red: the strip says no money moved in this environment and the banner says no money moved on this attempt. They are different claims and they must not be mistaken for each other, which is exactly why the strip is ink and mono rather than a second red band.

One element, three renders — not three components
All three are the same route, so the strip belongs to the checkout layout, above the header, and every state of that page gets it for free. If it were added per-state, one of them would eventually ship without it, and that one would be the declined state, where it matters most.
Ink above red, and the order matters
Environment first, then account state. Reading top to bottom you get none of this is real before this attempt failed, which is the order that prevents a tester filing a false bug — and the two never touch, because the header sits between them.
The declined card number changes too
In test mode the declined state shows 4000 0000 0000 0002, Stripe's decline card, not 4242. A tester reproducing a decline needs the card that causes one, and the strip names only the success card.
Mobile keeps it, at the same height
At 390 the sentence is the constraint. It stays one line at 11.5px mono down to 390 with 20px padding; below that the strip wraps to two lines and grows to 48px rather than truncating — a half-shown test warning is worse than none.
